Automated AST Analysis Platform & Web Portal
Project Brief

An enterprise monorepo featuring an automated AST-driven code analysis CLI tool (handoff-cli) and a fullstack Next.js web application (handoff-web). The CLI uses Tree-sitter parsers across 10+ languages to extract symbols, sanitizes secrets using entropy analysis, inspects Git history, and synthesizes technical handoff documentation using Google Generative AI. The web platform provides authentication, user onboarding, password recovery workflows, and a modern dashboard UI.

Accelerates developer onboarding by up to 80% through automated repository reverse-engineering and structural documentation generation. Mitigates compliance risks and data leaks by automatically scanning and redacting high-entropy secrets prior to AI model ingestion.

Capability manifest

Multi-language AST symbol extraction across TypeScript, JavaScript, Python, Go, Java, C++, C#, Ruby, Rust, and PHP powered by Tree-sitter

High-entropy secret detection and automated source code redaction engine

Git metadata, branch commit history, and diff summary parser using simple-git

Map-reduce domain chunking and report synthesis using Google Generative AI

Content hashing cache engine for incremental parsing performance

Standalone interactive HTML report generation with embedded Mermaid.js architecture diagrams

Fullstack web application built with Next.js App Router, Tailwind CSS v4, and React 19

Complete user authentication lifecycle including registration, verification, login, password recovery, and rate-limited API routes

Execution sequence

CLI Report Generation Flow

1

Operator executes handoff CLI command in target repository.

2

ASTExtractor scans repository files, builds directory tree, and parses AST symbols.

3

Sanitizer identifies and redacts high-entropy secrets and sensitive strings.

4

Map-reduce engine chunks sanitized code and requests AI summary from Google Generative AI.

5

Html generator outputs handoff-report.html and handoff-report.json.

User Registration & Identity Verification Flow

1

User accesses /register page in handoff-web UI.

2

User submits credentials which post to /api/register endpoint.

3

System creates user record and dispatches verification email via /api/resend.

4

User clicks link redirecting to /verify which posts token to /api/verify.

5

User gets redirected to /dash dashboard upon successful token validation.

System architecture

This repository is structured as an enterprise monorepo containing two main projects: handoff-cli (an AST analysis engine) and handoff-web (a Next.js 16 web portal). The CLI module leverages native Tree-sitter bindings for language parsing, simple-git for Git commit extraction, and @google/generative-ai for map-reduce document synthesis. The Web application utilizes Next.js App Router with React 19, Tailwind CSS v4, @supabase/ssr for authentication state management, and @upstash/ratelimit for API rate-limiting enforcement.

Data state & Schema

Supabase (PostgreSQL) & Upstash Redis

User authentication and persistent user state are backed by Supabase Auth and PostgreSQL. Rate limiting across API routes (/api/*) is enforced via Upstash Redis REST integration.

Entity / Table Schema & Relations
auth.users Managed by Supabase Auth; stores user IDs, hashed credentials, email verification statuses, and timestamps.
upstash_rate_limits Key-value cache records managed by Upstash Redis to track request frequencies and prevent API abuse.

Initialization

❯Clone repository and ensure Node.js (>=20.x) and pnpm/npm are installed.
❯Install dependencies at repository root: npm install.
❯Navigate to handoff-cli/ and copy sample env: cp .env.example .env (set GEMINI_API_KEY).
❯Build and test handoff CLI: cd handoff-cli && npm run build && npm start.
❯Navigate to handoff-web/ and configure environment variables in .env.local for Supabase and Upstash.
❯Run local web development server: cd handoff-web && npm run dev.
❯Open http://localhost:3000 to access the web application interface.
